# Troubleshooting Incorrect `absoluteURL` Configuration on Windows Installations

## Overview

When installing Gibbon in a local Windows development environment, an incorrectly configured `absoluteURL` can cause broken links and 404 errors when accessing modules.

This tutorial explains a common issue encountered when running Gibbon using AMPPS Apache and how to resolve it by correctly configuring the `absoluteURL` setting.

## Environment

This issue was identified in the following environment:

* Operating System: Windows 11
* Web Server: AMPPS Apache
* Database: MySQL/MariaDB
* Installation location:

```
C:\Program Files\Ampps\www\gibbon
```

The Gibbon application folder was copied into the AMPPS web root and accessed locally using:

```
http://localhost/gibbon
```

## Symptoms

After completing the installation, some Gibbon modules returned 404 errors.

Apache logs showed requests similar to:

```
GET /index.php?q=/modules/Attendance/attendance.php → 404

GET /index.php?q=/modules/Finance/invoices_manage.php → 404

GET /index.php?q=/modules/Calendar/calendar_view.php → 404
```

The installation completed successfully, but links generated by Gibbon did not include the installation directory.

## Cause

The generated URLs were incorrect.

The application generated links similar to:

```
http://localhost/index.php?q=/modules/Attendance/attendance.php
```

However, because Gibbon was installed in a subdirectory, the correct URL should have been:

```
http://localhost/gibbon/index.php?q=/modules/Attendance/attendance.php
```

The cause was an incorrect `absoluteURL` value in:

```
System Admin → System Settings
```

The value had been entered as:

```
http://localhost\gibbon
```

The backslash (`\`) is a Windows file path separator and should not be used in web URLs. URLs require forward slashes (`/`).

## Resolution

Update the `absoluteURL` setting to use the correct URL format:

Incorrect:

```
http://localhost\gibbon
```

Correct:

```
http://localhost/gibbon
```

After saving the change and refreshing the browser, all modules loaded correctly.

## Recommended Configuration

When setting the `absoluteURL`, ensure that it exactly matches the address used to access Gibbon.

Examples:

### Gibbon installed in the web root

```
https://school.example.com
```

### Gibbon installed in a subdirectory

```
https://school.example.com/gibbon
```

Avoid using Windows path notation:

```
https://school.example.com\gibbon
```

## Additional Troubleshooting Steps

If similar 404 errors occur:

1. Confirm that the Gibbon installation directory exists in the web root.
2. Confirm the URL used in the browser matches the configured `absoluteURL`.
3. Check that forward slashes (`/`) are used in URLs.
4. Clear the browser cache and test again.
5. Review Apache logs for the generated request paths.

## Conclusion

Correctly configuring the `absoluteURL` setting is an important step when installing Gibbon in a local or subdirectory-based environment.

This issue was caused by an incorrect URL format rather than missing files or a problem with the Apache server configuration. Ensuring the correct `absoluteURL` value allows Gibbon to generate valid internal links and load modules correctly.
